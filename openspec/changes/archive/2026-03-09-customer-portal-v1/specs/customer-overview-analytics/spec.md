## 新增需求

### 需求: 客户总览首页
客户门户必须提供以当前用户为中心的总览首页，统一展示余额、订阅、
近期消耗、关键指标与可执行的下一步操作。

#### 场景: 已登录用户进入总览首页
- **当** 已登录用户进入客户门户首页
- **那么** 系统必须展示属于当前用户的余额、当前订阅与近期消耗摘要
- **并且** 所有数据必须仅限当前用户权限范围

#### 场景: 用户查看首页快捷操作
- **当** 用户在总览页看到充值、升级套餐或查看日志等操作入口
- **那么** 系统必须允许其直接跳转到对应页面
- **并且** 保持与所点击指标相关的上下文

### 需求: 统一时间范围分析
客户门户必须提供统一的时间范围筛选能力，使趋势图、统计摘要与分析组件
在同一时间窗口下返回一致结果。

#### 场景: 用户切换最近 7 天或 30 天
- **当** 用户切换分析时间范围
- **那么** 系统必须刷新趋势图与统计摘要
- **并且** 不同图表必须使用一致的时间窗口

#### 场景: 用户使用自定义时间范围
- **当** 用户输入合法的自定义开始和结束时间
- **那么** 系统必须基于该范围重新查询分析数据
- **并且** 对非法时间范围给出明确反馈

### 需求: 风险洞察与建议动作
客户门户必须在识别到余额偏低、消耗异常增长或订阅即将不足等风险时，
显式提示用户，并提供可直接执行的动作入口。

#### 场景: 系统识别余额或订阅风险
- **当** 用户存在余额不足、异常增长或套餐即将耗尽的风险
- **那么** 系统必须在总览页展示显式提醒
- **并且** 提供前往充值、升级或查看日志的入口

#### 场景: 用户从洞察跳转到详情页
- **当** 用户点击洞察卡片或异常指标
- **那么** 系统必须进入对应的账单、日志或模型详情页
- **并且** 尽量带入当前筛选条件
