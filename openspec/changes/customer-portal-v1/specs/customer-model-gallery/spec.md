## 新增需求

### 需求: 模型目录展示
客户门户必须提供可浏览、可搜索、可筛选的模型目录，并展示模型的厂商、
标签、价格与端点类型等核心信息。

#### 场景: 用户浏览模型目录
- **当** 用户进入模型广场
- **那么** 系统必须展示可用模型列表及其核心属性
- **并且** 支持搜索、筛选与排序

#### 场景: 用户按条件筛选模型
- **当** 用户按厂商、标签、端点类型或关键字筛选模型
- **那么** 系统必须返回符合条件的模型集合
- **并且** 保持筛选结果与分页状态一致

### 需求: 模型详情查看
客户门户必须为模型提供统一详情视图，展示价格、能力标签、适用场景与
关键说明，并且详情体验必须与客户门户整体视觉一致。

#### 场景: 用户查看模型详情
- **当** 用户打开某个模型的详情
- **那么** 系统必须展示该模型的价格、能力标签与适用场景
- **并且** 保持与门户整体一致的详情交互方式

#### 场景: 用户查看模型相关说明
- **当** 模型存在额外的说明、端点信息或能力标签
- **那么** 系统必须在详情视图中展示这些信息
- **并且** 不要求用户跳出门户到其他页面查找

### 需求: 个人使用视角叠加
客户门户必须在模型列表或详情中优先展示与当前用户相关的近期使用信息，
并且在缺少个人数据时优雅降级为通用模型目录。

#### 场景: 用户查看个人常用模型
- **当** 当前用户存在近期模型使用数据
- **那么** 系统必须在模型列表或详情中突出显示常用模型或近期消耗
- **并且** 允许用户进一步查看相关日志

#### 场景: 当前用户缺少个人模型数据
- **当** 用户尚无足够的个人模型使用记录
- **那么** 系统必须退化为通用模型目录展示
- **并且** 不因为缺少个人数据而阻断模型浏览

### 需求: 模型与日志联动
客户门户必须支持从模型详情跳转到日志中心，并带入当前模型筛选条件。

#### 场景: 用户从模型详情查看使用记录
- **当** 用户在模型详情中选择查看自己的使用记录
- **那么** 系统必须跳转到日志中心并带入该模型筛选条件
- **并且** 允许用户从日志中心返回模型上下文
