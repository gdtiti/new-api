# customer-portal-shell 规范

## 目的
定义客户门户 `/app/*` 命名空间的壳层与导航：与管理后台隔离，统一受保护路由
与回跳逻辑，并保证桌面端与移动端信息架构一致且交互响应式。

## 需求
### 需求: 客户门户必须提供独立于管理后台的专用壳层
系统必须为已登录客户提供独立的客户门户壳层，并且不得要求用户理解管理后台的
导航结构才能访问自己的核心信息。

#### 场景: 已登录用户进入客户门户首页
- **当** 已登录用户访问客户门户首页
- **那么** 系统必须展示面向客户的专用导航结构
- **并且** 导航中必须优先呈现总览、分析、账单、日志与模型等客户任务入口

#### 场景: 客户门户不得默认暴露管理后台入口
- **当** 普通客户访问客户门户页面
- **那么** 系统必须隐藏仅面向管理员的导航项
- **并且** 不得要求用户先进入管理控制台再跳转到客户功能

### 需求: 客户门户必须统一处理受保护路由与回跳
系统必须将客户门户中的受保护页面统一纳入登录守卫，并且必须在完成认证后恢复
用户原本要访问的页面上下文。

#### 场景: 未登录用户访问受保护页面
- **当** 未登录用户直接访问客户门户中的受保护页面
- **那么** 系统必须将用户重定向到客户登录入口
- **并且** 记录其原始目标页面用于登录后的回跳

#### 场景: 登录后返回原始页面
- **当** 用户完成认证并重新进入客户门户
- **那么** 系统必须优先跳转回其原始目标页面
- **并且** 尽量保留必要的筛选参数或上下文参数

### 需求: 客户门户必须在桌面与移动端保持一致的信息架构
系统必须在不同设备形态下保持一致的信息架构与导航语义，只允许交互布局发生响
应式变化。

#### 场景: 桌面端使用客户门户
- **当** 用户在桌面端访问客户门户
- **那么** 系统必须提供清晰的主导航、顶部状态区与主内容区
- **并且** 不得因页面切换导致主要入口位置频繁变化

#### 场景: 移动端使用客户门户
- **当** 用户在移动端访问客户门户
- **那么** 系统必须以适合移动端的导航形式呈现同一组核心入口
- **并且** 页面名称、顺序与信息架构语义必须与桌面端保持一致
